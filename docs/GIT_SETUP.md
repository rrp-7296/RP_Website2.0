## 2. What Is Tracked vs Ignored

### ✅ Always Committed (Tracked)
| Path | Reason |
|------|--------|
| `backend/app/` | All Python source code |
| `backend/requirements.txt` | Python dependencies list |
| `backend/.env.example` | Template — safe, no real secrets |
| `backend/alembic/` | Database migration scripts |
| `backend/uploads/.gitkeep` | Keeps the folder structure |
| `ui/src/` | All React/TypeScript source code |
| `ui/public/` | Static assets (images, fonts) |
| `ui/android/` | Capacitor Android project |
| `ui/ios/` | Capacitor iOS project |
| `ui/package.json` | Node dependencies list |
| `ui/.env.development` | Dev config (no secrets) |
| `docs/` | All documentation |
| `start.bat`, `start.ps1` | Dev startup scripts |

### ❌ Never Committed (Ignored via `.gitignore`)
| Path | Reason |
|------|--------|
| `backend/.env` | Contains JWT secret, DB passwords |
| `backend/venv/` | Large virtual env — install from `requirements.txt` |
| `backend/test.db` | Local dev DB — each dev has their own |
| `backend/uploads/*` | Binary files — use cloud storage in production |
| `ui/node_modules/` | Large npm packages — install from `package.json` |
| `ui/dist/` | Build output — regenerated by `npm run build` |
| `ui/.env.production` | May contain server IP or API keys |
| `ui/android/app/build/` | Compiled APKs — generated by Android Studio |
| `*.keystore`, `*.jks` | Android signing keys — must never be shared |

## 4. Connect to GitHub

### Step 1 — Create a New Repository on GitHub

1. Go to **https://github.com/new**
2. Repository name: `website2.0` (or `rakeshwar-portfolio`)
3. Set to **Private** (recommended — contains client code)
4. ⚠️ **Do NOT** initialize with README, .gitignore, or license (repo already has these)
5. Click **Create repository**

### Step 2 — Link Local Repo to GitHub

```bash
cd c:\Old_Website\Website2.0

# Add GitHub as the remote origin
git remote add origin https://github.com/YOUR_USERNAME/website2.0.git

# Rename branch from master to main (GitHub standard)
git branch -M main

# Push all code to GitHub for the first time
git push -u origin main
```

### Step 3 — Verify

```bash
# Check remote is set correctly
git remote -v
# Should show:
# origin  https://github.com/YOUR_USERNAME/website2.0.git (fetch)
# origin  https://github.com/YOUR_USERNAME/website2.0.git (push)
```

### Step 4 — Authenticate with GitHub

When you push for the first time, Git will ask for authentication:

**Option A — Personal Access Token (Recommended)**
1. Go to GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)**
2. Click **Generate new token**
3. Select scopes: `repo` (full control)
4. Copy the token → use it as your **password** when Git prompts

**Option B — GitHub CLI**
```bash
# Install GitHub CLI: https://cli.github.com/
gh auth login
# Follow the browser-based login flow
```

## 5. Daily Development Workflow

### Standard Flow

```bash
# 1. Before starting work — pull latest changes from team
git pull origin main

# 2. Make your code changes...

# 3. See what changed
git status

# 4. See exact line-by-line changes
git diff

# 5. Stage all changed files
git add .

# OR stage specific files only
git add ui/src/components/Hero.tsx
git add backend/app/routers/blog.py

# 6. Commit with a descriptive message
git commit -m "feat: add dark mode toggle to navbar"

# 7. Push to GitHub
git push origin main
```

### Quick One-liner (after approving changes)

```bash
git add . ; git commit -m "fix: correct gallery image URL" ; git push
```

## 6. Branch Strategy

Use branches to keep `main` stable and always deployable.

```
main        ← Production-ready code only. Always works.
  └── dev   ← Active development. Merge into main when stable.
       └── feature/gallery-lightbox   ← One feature at a time
       └── fix/admin-login-bug
       └── hotfix/deployment-crash
```

### Creating and Using Branches

```bash
# Create a new feature branch and switch to it
git checkout -b feature/gallery-lightbox

# ... make changes, commit as usual ...
git add .
git commit -m "feat: add lightbox to gallery page"

# Push the branch to GitHub
git push origin feature/gallery-lightbox

# When done, merge back into main
git checkout main
git merge feature/gallery-lightbox

# Delete the feature branch (cleanup)
git branch -d feature/gallery-lightbox
git push origin --delete feature/gallery-lightbox
```

## 7. Commit Message Convention

Use the **Conventional Commits** format for a clean, readable history:

```
<type>: <short description>

[optional longer body]
```

### Types

| Type | When to Use | Example |
|------|-------------|---------|
| `feat` | New feature | `feat: add newsletter subscription` |
| `fix` | Bug fix | `fix: gallery images not loading on mobile` |
| `ui` | Visual/style change | `ui: improve hero section spacing` |
| `refactor` | Code cleanup, no behavior change | `refactor: extract API calls to service file` |
| `docs` | Documentation only | `docs: add mobile build guide` |
| `chore` | Config, deps, tooling | `chore: update vite to v8` |
| `hotfix` | Urgent production fix | `hotfix: fix broken admin login` |
| `perf` | Performance improvement | `perf: lazy load gallery images` |

### Good Commit Examples

```bash
git commit -m "feat: add timeline filter by year"
git commit -m "fix: admin dashboard stats not refreshing"
git commit -m "ui: update color palette to tricolor theme"
git commit -m "docs: add git setup guide to docs folder"
git commit -m "chore: add .gitattributes for line ending config"
```

## 8. Undoing Changes

### Undo uncommitted changes to a file

```bash
# Discard all changes to one file (restore to last commit)
git checkout -- ui/src/components/Hero.tsx

# Discard ALL uncommitted changes (careful — permanent!)
git checkout -- .
```

### Undo a staged file (unstage it)

```bash
# Remove a file from staging area (changes kept on disk)
git reset HEAD ui/src/pages/Gallery.tsx
```

### Undo the last commit (keep changes)

```bash
# "Soft" undo — undoes the commit but keeps files staged
git reset --soft HEAD~1
```

### Undo the last commit (discard changes)

```bash
# "Hard" undo — permanently removes last commit and all its changes
git reset --hard HEAD~1
```

### Revert a pushed commit (safe for shared branches)

```bash
# Creates a NEW commit that undoes a specific commit
git revert <commit-hash>
git push
```

## 10. Common Issues & Fixes

### ❌ "fatal: not a git repository"

You're not in the right folder. Navigate to the project root:
```bash
cd c:\Old_Website\Website2.0
```

---

### ❌ "Updates were rejected because the remote contains work you do not have"

Someone else pushed changes. Pull first:
```bash
git pull origin main
# Resolve any merge conflicts, then push again
git push origin main
```

---

### ❌ Accidentally committed `.env` or `test.db`

**Remove the file from git tracking (but keep it on disk):**
```bash
git rm --cached backend/.env
git rm --cached backend/test.db
git commit -m "chore: remove secrets from git tracking"
git push
```

Then add the file to `.gitignore` to prevent it happening again.

---

### ❌ "Permission denied (publickey)"

Switch to HTTPS instead of SSH:
```bash
git remote set-url origin https://github.com/YOUR_USERNAME/website2.0.git
```

---

### ❌ Merge conflict

Git will mark conflicting files like this:
```
<<<<<<< HEAD
your local change
=======
incoming change from remote
>>>>>>> origin/main
```

Open the file, manually pick the correct version (delete the markers), then:
```bash
git add .
git commit -m "fix: resolve merge conflict in Hero.tsx"
```
